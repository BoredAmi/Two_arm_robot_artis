\section{Najczęstsze błędy i ich rozwiązania}

\subsection{Problemy z połączeniem robota}
\textbf{Błąd:} Nie można połączyć się z robotem. Aplikacja wyświetla komunikat o błędzie połączenia.

\textbf{Rozwiązanie:}
\begin{itemize}
    \item Sprawdź, czy robot jest włączony i w trybie automatycznym.
    \item Upewnij się, że kabel Ethernet jest prawidłowo podłączony między komputerem a robotem.
    \item Zweryfikuj adres IP robota (domyślnie 192.168.125.1) i porty (1025 dla prawego ramienia, 1026 dla lewego).
    \item Sprawdź ustawienia firewall na komputerze – upewnij się, że TCP połączenia na portach 1025 i 1026 są dozwolone.
    \item Uruchom ponownie aplikację na robocie i komputerze.
\end{itemize}

\subsection{Błędy podczas kalibracji}
\textbf{Błąd:} Robot nie kalibruje się lub wyświetla błędy podczas uruchamiania aplikacji.

\textbf{Rozwiązanie:}
\begin{itemize}
    \item Upewnij się, że robot jest w pozycji kalibracyjnej (widoczne ząbki i wskaźniki na zdjęciach).
    \item Potwierdź wszystkie błędy na panelu robota przyciskiem "Acknowledge errors".
    \item Przejdź w tryb manualny, a następnie wróć do trybu automatycznego.
    \item Ustaw "pointer to main" na obu ramionach.
\end{itemize}

\subsection{Problemy z kamerą}
\textbf{Błąd:} Nie można zrobić zdjęcia lub kamera nie działa.

\textbf{Rozwiązanie:}
\begin{itemize}
    \item Sprawdź, czy kamera jest podłączona do komputera i rozpoznawana przez system (np. w Menedżerze urządzeń w Windows).
    \item Upewnij się, że inne aplikacje nie używają kamery.
    \item Spróbuj zmienić indeks kamery w ustawieniach aplikacji (domyślnie 0).
    \item Jeśli kamera zewnętrzna, sprawdź połączenie USB i zasilanie.
    \item Zamknij i uruchom ponownie aplikację.
\end{itemize}

\subsection{Błędy generowania obrazu przez OpenAI}
\textbf{Błąd:} OpenAI nie generuje obrazu lub zwraca błąd API.

\textbf{Rozwiązanie:}
\begin{itemize}
    \item Sprawdź połączenie internetowe – wymagane stabilne łącze.
    \item Upewnij się, że klucz API OpenAI jest prawidłowo skonfigurowany w aplikacji.
    \item Sprawdź limit wykorzystania API – jeśli przekroczony, poczekaj lub wpłać pieniądze.
    \item Spróbuj ponownie z tym samym zdjęciem lub wykonaj nowe zdjęcie.
    \item Jeśli błąd trwa, sprawdź status usług OpenAI.
\end{itemize}

\subsection{Problemy z przetwarzaniem obrazu}
\textbf{Błąd:} Obraz po przetworzeniu ma złe kontury lub jest nieczytelny.

\textbf{Rozwiązanie:}
\begin{itemize}
    \item Wypróbuj inną metodę detekcji krawędzi (threshold, canny lub adaptive) w ustawieniach.
    \item Dostrój parametry jakości (wyższa jakość dla lepszych wyników, ale dłuższy czas przetwarzania).
    \item Wykonaj lepsze zdjęcie – upewnij się o dobrym oświetleniu i ostrości.
    \item Sprawdź, czy obraz nie jest zbyt złożony; uprość tło lub pozycję.
\end{itemize}

\subsection{Błędy podczas rysowania}
\textbf{Błąd:} Robot zatrzymuje się podczas rysowania lub występuje kolizja.

\textbf{Rozwiązanie:}
\begin{itemize}
    \item Włącz tryb manualny i odjedź ramionami w bezpieczne miejsce
    \item Zwiększ bufor kolizyjny w ustawieniach (domyślnie 40 mm).
    \item Sprawdź marginesy bezpieczeństwa (domyślnie 10 mm od krawędzi).
    \item Jeśli timeout, zwiększ timeout w ustawieniach lub sprawdź połączenie.
    \item W przypadku zatrzymania, użyj przycisku awaryjnego stop na robocie.
\end{itemize}

\subsection{Problemy z rozpoznawaniem głosu}
\textbf{Błąd:} VOSK nie rozpoznaje poleceń głosowych.

\textbf{Rozwiązanie:}
\begin{itemize}
    \item Upewnij się, że model VOSK (vosk-model-small-pl-0.22) jest pobrany i w odpowiednim folderze.
    \item Mów wyraźnie po polsku, w cichym środowisku.
    \item Dostrój czułość mikrofonu w ustawieniach systemu.
    \item Jeśli nie działa, użyj komend tekstowych zamiast głosowych.
    \item 
\end{itemize}
\subsection{Inne problemy}
\textbf{Błąd:} Aplikacja się zawiesza lub wyświetla błędy Python.

\textbf{Rozwiązanie:}
\begin{itemize}
    \item Sprawdź w terminalu jakie błędy wyskakują.
    \item Sprawdź, czy wszystkie wymagane biblioteki są zainstalowane (np. OpenCV, Matplotlib, Shapely).

    \item Jeśli błąd trwa, zrestartuj komputer i spróbuj ponownie.
\end{itemize}

\section{FAQ}

\subsection{Jak działa cały proces tworzenia rysunku przez robota?}
Cały proces rozpoczyna się od wykonania zdjęcia za pomocą kamery podłączonej do komputera. Następnie zdjęcie jest wysyłane poprzez API OpenAI z wybranym promptem (portret lub karykatura), aby wygenerować nowy obraz w wybranym stylu. Zwrócony obraz jest przetwarzany przez jedną z trzech metod detekcji krawędzi (threshold, canny lub adaptive), upraszczany do konturów, obracany i optymalizowany pod kątem ścieżki rysowania. Na koniec robot ABB YuMi rysuje obraz na podstawie wygenerowanych współrzędnych.


\subsection{Jakie są metody przetwarzania obrazu?}
System oferuje trzy metody detekcji krawędzi:
\begin{itemize}
    \item - \textbf{Threshold}: Prosta binaryzacja obrazu ze sztywno ustaloną jasnością odcięcia (dobra dla dobrego światła) 1 gdzie jest ciemniej, 0 gdzie jaśniej.
    \item \textbf{Canny}: Znajdywanie zmian jasności w miejscu zmian dajemy 1, gdzie nie ma zmian dajemy 0.
    \item \textbf{Adaptive}: To samo co Threshold, ale sam dobiera parametry (bardziej uniwersalny).
\end{itemize}


\subsection{Po co przetwarzamy zdjęcia w chmurze z AI?}
Możemy uzyskać zdecydowanie ładniejsze proste linie żeby stworzyć najlepszy obrazek do rysowania inaczej robot by pracował ekstremalnie długo żeby narysować każdy cień we włosach itp.

\subsection{Jak dokładnie przechodzimy z binarnego obrazu na kontury?}
Po zastosowaniu jednej z trzech metod detekcji krawędzi (threshold, canny lub adaptive), obraz staje się binarny – czarno-biały, gdzie białe piksele reprezentują krawędzie, a czarne tło. Następnie używamy algorytmu który skanuje obraz i identyfikuje połączone grupy białych pikseli jako kontury. Każdy kontur to lista punktów współrzędnych (x,y), które opisują kształt linii. Kontury są upraszczane za pomocą approxPolyDP() z parametrem epsilon, aby zredukować liczbę punktów bez utraty kształtu – to kluczowe dla wydajności, bo robot nie musi rysować każdego piksela. Na koniec kontury są filtrowane: małe artefakty są usuwane, a duże kontury dzielone na segmenty dla lepszej kontroli.

\subsection{Jak działa tworzenie trasy rysowania wzdłuż konturu?}
Gdy mamy kontury jako listy punktów, system tworzy trasę rysowania, traktując każdy kontur jak ścieżkę. Punkty są łączone w sekwencje, tworząc linię ciągłą. Dla płynności stosujemy wygładzanie – algorytm Bézier interpoluje punkty, eliminując ostre kąty. Opcjonalnie włączamy TSP (Traveling Salesman Problem), który optymalizuje kolejność rysowania konturów, minimalizując czas przejścia między nimi (np. rysujemy najbliższy kontur następny). Ścieżka jest skalowana do współrzędnych robota (np. 290x210 mm) z marginesami bezpieczeństwa. W trybie dual-arm ścieżki są dzielone między ramiona, a każdy punkt ma przypisany czas ruchu dla synchronizacji.

\subsection{Jak system inteligentnie dzieli pracę między dwa ramiona robota?}
W trybie dual-arm system używa zaawansowanego algorytmu master-slave assignment, ale uwaga – role master i slave nie są stałe! System dynamicznie decyduje, które ramię zostaje "mózgiem operacji" (masterem), a które "wsparciem" (slave), w zależności od położenia konturów, ale zazwyczaj zamieniają się co kontur. Kluczowe są specjalne strefy: lewe ramię ma zakazaną strefę (0,0 do 130,40 mm), więc zawsze unika tego obszaru, by nie kolidować z podstawą robota. System stosuje bufor kolizyjny (domyślnie 40 mm) – kołowy "bąbel bezpieczeństwa" wokół mastera oraz "ogon" od tego "bąbla" do krawędzi kartki w stronę mastera, do którego slave nie może wejść. Algorytm sprawdza nakładanie się wielokątów konturów z tymi buforami, inteligentnie przypisując zadania, aby uniknąć kolizji. Dodatkowo, kontury są sortowane wg pozycji: bliższe ramię dostaje priorytet. Ramiona między konturami podróżują w kształcie kanciastego U żeby uniknąć kolizji podczas tranzycji, także pozwala to ograniczyć czas robotów spędzony bardzo blisko siebie. To wszystko razem pracując pozwala na rysowanie używając dwóch ramion.

\subsection{Jak działa komunikacja między komputerem a robotem?}
Komunikacja między komputerem a robotem ABB YuMi odbywa się poprzez protokół TCP/IP. Komputer łączy się z robotem na dwóch portach: 1025 dla prawego ramienia i 1026 dla lewego ramienia. Wysyłane są komendy tekstowe, takie jak "MOVE,x,y" do przesunięcia ramienia, "BATCH$,x_1,y_1,x_2,y_2$,..." do wysłania grupy punktów, "PEN UP" i "PEN DOWN" do kontroli narzędzia. W trybie dual-arm synchronizacja ramion jest realizowana za pomocą barier wątków i komend "WAIT". Tryb batch grupuje punkty w paczki (maksymalnie 15 punktów), co zwiększa wydajność. System obsługuje błędy poprzez timeouty, ponowne próby i wykrywanie rozłączeń. Robot potwierdza wykonanie komend odpowiedzią "OK".

\section{Dostrajanie algorytmów przetwarzania obrazu}

\subsection{Parametry detekcji krawędzi}

\subsubsection{Threshold - parametry binaryzacji}
\textbf{Lokalizacja:} \texttt{image\_processor.py}, funkcja \texttt{detect\_edges\_threshold()}

\textbf{Kluczowe parametry:}
\begin{itemize}
    \item \texttt{threshold\_value} - Wartość odcięcia (domyślnie 127)
    \item \texttt{max\_value} - Maksymalna wartość dla pikseli powyżej progu
\end{itemize}

\textbf{Jak zmienić:}
\begin{enumerate}
    \item Otwórz plik \texttt{image\_processor.py}
    \item Znajdź funkcję \texttt{detect\_edges\_threshold()}
    \item Zmodyfikuj wartość \texttt{threshold\_value}
\end{enumerate}

\textbf{Wpływ na system:}
\begin{itemize}
    \item Niższa wartość - więcej wykrytych krawędzi
    \item Wyższa wartość - mniej wykrytych krawędzi
    \item Optymalna wartość zależy od oświetlenia zdjęcia
\end{itemize}

\subsubsection{Canny - parametry detekcji}
\textbf{Lokalizacja:} \texttt{image\_processor.py}, funkcja \texttt{detect\_edges\_canny()}

\textbf{Kluczowe parametry:}
\begin{itemize}
    \item \texttt{min\_threshold} - Minimalny próg (domyślnie 50)
    \item \texttt{max\_threshold} - Maksymalny próg (domyślnie 150)
\end{itemize}

\textbf{Jak zmienić:}
\begin{enumerate}
    \item Otwórz plik \texttt{image\_processor.py}
    \item Znajdź funkcję \texttt{detect\_edges\_canny()}
    \item Dostosuj wartości progów
\end{enumerate}

\textbf{Wpływ na system:}
\begin{itemize}
    \item Mniejsze różnice między progami - więcej detali
    \item Większe różnice między progami - mniej detali
    \item Dobiera się eksperymentalnie dla danego typu obrazu
\end{itemize}

\subsubsection{Adaptive - parametry adaptacyjne}
\textbf{Lokalizacja:} \texttt{image\_processor.py}, funkcja \texttt{detect\_edges\_adaptive()}

\textbf{Kluczowe parametry:}
\begin{itemize}
    \item \texttt{block\_size} - Rozmiar bloku sąsiedztwa (domyślnie 11)
    \item \texttt{C} - Stała odejmowana od średniej (domyślnie 2)
\end{itemize}

\textbf{Wpływ na system:}
\begin{itemize}
    \item Większy block\_size - bardziej płynne przejścia
    \item Mniejszy block\_size - bardziej szczegółowa detekcja
    \item Parametr C wpływa na czułość detekcji
\end{itemize}

\subsection{Parametry upraszczania konturów}

\subsubsection{Parametr epsilon approxPolyDP}
\textbf{Lokalizacja:} \texttt{image\_processor.py}, funkcja \texttt{simplify\_contours()}

\textbf{Wartość domyślna:} 0.01 (1\% długości konturu)

\textbf{Jak zmienić:}
\begin{enumerate}
    \item Otwórz plik \texttt{image\_processor.py}
    \item Znajdź wywołanie \texttt{cv2.approxPolyDP()}
    \item Zmodyfikuj wartość epsilon
\end{enumerate}

\textbf{Wpływ na system:}
\begin{itemize}
    \item Mniejsze epsilon - więcej punktów, dokładniejsze kontury
    \item Większe epsilon - mniej punktów, prostsze kontury
    \item Zbyt małe epsilon spowalnia rysowanie
    \item Zbyt duże epsilon traci detale
\end{itemize}

\subsubsection{Minimalna długość konturu}
\textbf{Lokalizacja:} \texttt{image\_processor.py}, funkcja \texttt{filter\_contours()}

\textbf{Wartość domyślna:} 10 pikseli

\textbf{Jak zmienić:}
\begin{enumerate}
    \item Otwórz plik \texttt{image\_processor.py}
    \item Znajdź warunek filtrowania konturów
    \item Dostosuj wartość minimalnej długości
\end{enumerate}

\textbf{Wpływ na system:}
\begin{itemize}
    \item Mniejsza wartość - więcej małych detali
    \item Większa wartość - czystszy obraz, mniej szumu
    \item Zależy od rozdzielczości wejściowego obrazu
\end{itemize}
