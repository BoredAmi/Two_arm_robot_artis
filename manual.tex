\section{Most Common Errors and Solutions}

\subsection{Robot Connection Problems}
\textbf{Error:} Unable to connect to the robot. The application displays a connection error message.

\textbf{Solution:}
\begin{itemize}
\item Check if the robot is turned on and in automatic mode.
\item Make sure the Ethernet cable is correctly connected between the computer and the robot.
\item Verify the robot's IP address (default is 192.168.125.1) and ports (1025 for the right arm, 1026 for the left).
\item Check your computer's firewall settings—ensure that TCP connections on ports 1025 and 1026 are allowed.
\item Restart the application on both the robot and the computer.
\end{itemize}

\subsection{Calibration Errors}
\textbf{Error:} The robot doesn't calibrate or displays errors when the application starts.

\textbf{Solution:}
\begin{itemize}
\item Make sure the robot is in the calibration position (visible gears and indicators in the photos).
\item Acknowledge all errors on the robot panel using the "Acknowledge errors" button.
\item Switch to manual mode, then return to automatic mode.
\item Set the "pointer to main" on both arms.
\end{itemize}

\subsection{Camera Problems}
\textbf{Error:} Unable to take a picture or the camera isn't working.

\textbf{Solution:}
\begin{itemize}
\item Check if the camera is connected to the computer and recognized by the system (e.g., in Windows Device Manager).
\item Make sure no other applications are using the camera.
\item Try changing the camera index in the application settings (default is 0).
\item If it's an external camera, check the USB connection and power supply.
\item Close and restart the application.
\end{itemize}

\subsection{OpenAI Image Generation Errors}
\textbf{Error:} OpenAI doesn't generate an image or returns an API error.

\textbf{Solution:}
\begin{itemize}
\item Check your internet connection—a stable link is required.
\item Ensure that the OpenAI API key is correctly configured in the application.
\item Check the API usage limit—if it's exceeded, wait or top up your account.
\item Try again with the same photo or take a new one.
\item If the error persists, check the status of OpenAI services.
\end{itemize}

\subsection{Image Processing Problems}
\textbf{Error:} The processed image has poor contours or is unreadable.

\textbf{Solution:}
\begin{itemize}
\item Try a different edge detection method (threshold, canny, or adaptive) in the settings.
\item Fine-tune the quality parameters (higher quality for better results, but longer processing time).
\item Take a better photo—ensure good lighting and sharpness.
\item Check if the image is too complex; simplify the background or position.
\end{itemize}

\subsection{Drawing Errors}
\textbf{Error:} The robot stops while drawing or a collision occurs.

\textbf{Solution:}
\begin{itemize}
\item Switch to manual mode and move the arms to a safe location.
\item Increase the collision buffer in the settings (default is 40 mm).
\item Check the safety margins (default is 10 mm from the edge).
\item If a timeout occurs, increase the timeout in the settings or check the connection.
\item In case of a stop, use the emergency stop button on the robot.
\end{itemize}

\subsection{Voice Recognition Problems}
\textbf{Error:} VOSK doesn't recognize voice commands.

\textbf{Solution:}
\begin{itemize}
\item Make sure the VOSK model (vosk-model-small-pl-0.22) is downloaded and in the correct folder.
\item Speak clearly in Polish, in a quiet environment.
\item Adjust the microphone sensitivity in your system settings.
\item If it doesn't work, use text commands instead of voice.
\end{itemize}
\subsection{Other Problems}
\textbf{Error:} The application freezes or displays Python errors.

\textbf{Solution:}
\begin{itemize}
\item Check the terminal for any errors.
\item Verify that all required libraries are installed (e.g., OpenCV, Matplotlib, Shapely).
\item Run the application from the command line to see detailed errors.
\item Check RAM availability—processing large images requires resources.
\item Update Python to version 3.8+.
\item If the error persists, restart the computer and try again.
\end{itemize}

\section{FAQ}

\subsection{How does the entire drawing process work?}
The whole process begins with a photo taken by a camera connected to the computer. This photo is then sent via the OpenAI API with a chosen prompt (portrait or caricature) to generate a new image in the selected style. The returned image is processed using one of three edge detection methods (threshold, canny, or adaptive), simplified to contours, rotated, and optimized for the drawing path. Finally, the ABB YuMi robot draws the image based on the generated coordinates.

\subsection{What are the image processing methods?}
The system offers three edge detection methods:
\begin{itemize}
\item - \textbf{Threshold}: Simple binarization of the image with a rigidly set brightness cutoff (good for good lighting). 1 where it's darker, 0 where it's lighter.
\item \textbf{Canny}: Finds changes in brightness. Where there are changes, we get 1; where there are no changes, we get 0.
\item \textbf{Adaptive}: The same as Threshold, but it automatically selects the parameters (more universal).
\end{itemize}

\subsection{Why do we process images in the cloud with AI?}
We can get much nicer, simpler lines to create the best image for drawing. Otherwise, the robot would work for an extremely long time to draw every shadow in the hair, etc.

\subsection{How exactly do we convert a binary image to contours?}
After applying one of the three edge detection methods (threshold, canny, or adaptive), the image becomes binary—black and white, where white pixels represent edges and black is the background. We then use an algorithm that scans the image and identifies connected groups of white pixels as contours. Each contour is a list of coordinate points (x,y) that describe the shape of the line. The contours are simplified using `approxPolyDP()` with an epsilon parameter to reduce the number of points without losing the shape—this is crucial for efficiency because the robot doesn't have to draw every single pixel. Finally, the contours are filtered: small artifacts are removed, and large contours are split into segments for better control.

\subsection{How does creating the drawing path along the contour work?}
When we have contours as lists of points, the system creates a drawing path, treating each contour as a route. The points are connected in a sequence, creating a continuous line. For fluidity, we use smoothing—a Bézier algorithm interpolates the points, eliminating sharp corners. We can optionally enable TSP (Traveling Salesman Problem), which optimizes the order of drawing contours, minimizing the travel time between them (e.g., drawing the nearest contour next). The path is scaled to the robot's coordinates (e.g., 290x210 mm) with safety margins. In dual-arm mode, the paths are split between the arms, and each point is assigned a movement time for synchronization.

\subsection{How does the system intelligently split work between two robot arms?}
In dual-arm mode, the system uses an advanced master-slave assignment algorithm, but note—the master and slave roles are not fixed! The system dynamically decides which arm becomes the "operation brain" (master) and which is the "support" (slave), depending on the contour's position, but they usually switch roles with each contour. Special zones are key: the left arm has a forbidden zone (0,0 to 130,40 mm), so it always avoids this area to prevent collision with the robot base. The algorithm uses a collision buffer (default 40 mm)—a circular "safety bubble" around the master and a "tail" from this "bubble" towards the master's side of the paper, which the slave cannot enter. The algorithm checks for the overlap of contour polygons with these buffers, intelligently assigning tasks to avoid collisions. Additionally, contours are sorted by position: the closer arm gets priority. The arms travel in a sharp U-shape between contours to avoid collisions during transitions and to limit the time the robots spend very close to each other. All this together allows for two-arm drawing.

\subsection{How does communication between the computer and the robot work?}
Communication between the computer and the ABB YuMi robot takes place via the TCP/IP protocol. The computer connects to the robot on two ports: 1025 for the right arm and 1026 for the left arm. Text commands are sent, such as "MOVE,x,y" to move an arm, "BATCH$,x_1,y_1,x_2,y_2$,..." to send a group of points, and "PEN UP" and "PEN DOWN" to control the tool. In dual-arm mode, arm synchronization is achieved using thread barriers and "WAIT" commands. The batch mode groups points into packets (maximum 15 points), which increases efficiency. The system handles errors through timeouts, retries, and disconnection detection. The robot confirms command execution with an "OK" response.

\section{Tuning Image Processing Algorithms}

\subsection{Edge Detection Parameters}

\subsubsection{Threshold - Binarization Parameters}
\textbf{Location:} \texttt{image\_processor.py}, function \texttt{detect\_edges\_threshold()}

\textbf{Key Parameters:}
\begin{itemize}
\item \texttt{threshold\_value} - Cutoff value (default 127)
\item \texttt{max\_value} - Maximum value for pixels above the threshold
\end{itemize}

\textbf{How to Change:}
\begin{enumerate}
\item Open the \texttt{image\_processor.py} file
\item Find the \texttt{detect\_edges\_threshold()} function
\item Modify the \texttt{threshold\_value}
\end{enumerate}

\textbf{Effect on the System:}
\begin{itemize}
\item Lower value - more edges detected
\item Higher value - fewer edges detected
\item The optimal value depends on the photo's lighting
\end{itemize}

\subsubsection{Canny - Detection Parameters}
\textbf{Location:} \texttt{image\_processor.py}, function \texttt{detect\_edges\_canny()}

\textbf{Key Parameters:}
\begin{itemize}
\item \texttt{min\_threshold} - Minimum threshold (default 50)
\item \texttt{max\_threshold} - Maximum threshold (default 150)
\end{itemize}

\textbf{How to Change:}
\begin{enumerate}
\item Open the \texttt{image\_processor.py} file
\item Find the \texttt{detect\_edges\_canny()} function
\item Adjust the threshold values
\end{enumerate}

\textbf{Effect on the System:}
\begin{itemize}
\item Smaller difference between thresholds - more detail
\item Larger difference between thresholds - less detail
\item Chosen experimentally for a given image type
\end{itemize}

\subsubsection{Adaptive - Adaptive Parameters}
\textbf{Location:} \texttt{image\_processor.py}, function \texttt{detect\_edges\_adaptive()}

\textbf{Key Parameters:}
\begin{itemize}
\item \texttt{block\_size} - Neighborhood block size (default 11)
\item \texttt{C} - Constant subtracted from the mean (default 2)
\end{itemize}

\textbf{Effect on the System:}
\begin{itemize}
\item Larger block\_size - smoother transitions
\item Smaller block\_size - more detailed detection
\item Parameter C affects detection sensitivity
\end{itemize}

\subsection{Contour Simplification Parameters}

\subsubsection{epsilon Parameter for `approxPolyDP`}
\textbf{Location:} \texttt{image\_processor.py}, function \texttt{simplify\_contours()}

\item Larger epsilon - fewer points, simpler contours
\item Too small epsilon slows down drawing
\item Too large epsilon loses detail
\end{itemize}

\textbf{Effect on the System:}
\begin{itemize}

\item Larger value - cleaner image, less noise
\item Depends on the resolution of the input image
\end{itemize}

\section{System Pipeline Overview}

This section provides an extremely detailed, step-by-step breakdown of the entire function call pipeline in the Robot Drawing System project, from user interaction through robot execution completion.

\subsection{System Architecture Overview}

The system consists of 6 main modules:
\begin{itemize}
\item \texttt{simple\_gui.py}: Main GUI interface and orchestration
\item \texttt{robot\_drawer.py}: High-level drawing orchestration
\item \texttt{image\_processor.py}: Image processing and edge detection
\item \texttt{coordinate\_transformer.py}: Coordinate transformation and optimization
\item \texttt{robot\_communication.py}: Low-level robot TCP/IP communication
\item \texttt{voice\_commands.py}: Voice recognition and command processing
\item \texttt{visualizer.py}: Data visualization and plotting
\end{itemize}

\subsection{Detailed Pipeline Flow}

\subsubsection{Phase 1: Application Initialization}

\paragraph{GUI Startup (\texttt{simple\_gui.py})}
\begin{enumerate}
\item \texttt{SimpleRobotGUI.\_\_init\_\_()}:
	\begin{itemize}
	\item Creates Tkinter root window
	\item Loads configuration from \texttt{robot\_gui\_config.json} via \texttt{\_load\_config()}
	\item Initializes \texttt{RobotDrawer} instance with default parameters (290x210mm workspace, center origin, TSP enabled)
	\item Sets up voice command listener with \texttt{VoiceCommandListener}
	\item Calls \texttt{create\_simple\_interface()} to build UI
	\item Starts connection status update loop with \texttt{root.after(100, self.\_update\_connection\_display)}
	\end{itemize}

\paragraph{Voice System Initialization (\texttt{voice\_commands.py})}
\begin{enumerate}
\item \texttt{VoiceCommandListener.\_\_init\_\_()}:
	\begin{itemize}
	\item Sets up VOSK model path (handles both development and packaged environments)
	\item Initializes audio queue and threading components
	\item Prepares callback system for recognized commands
	\end{itemize}
\end{enumerate}

\subsubsection{Phase 2: Image Acquisition}

\paragraph{Camera/Image Input Methods}

\textbf{Method A: Robot Camera (\texttt{simple\_gui.py})}
\begin{enumerate}
\item User clicks "1. TAKE PICTURE" $\rightarrow$ \texttt{get\_picture\_from\_robot()}
\item \texttt{get\_picture\_from\_robot()} $\rightarrow$ \texttt{ready\_robot\_without\_camera()} $\rightarrow$ \texttt{RobotController.start\_without\_camera()}
\item \texttt{RobotController.start\_without\_camera()} $\rightarrow$ \texttt{\_send\_command("READY\textbackslash n")} to robot
\item Robot responds with "OK" after initialization
\item \texttt{get\_picture\_from\_robot()} $\rightarrow$ \texttt{\_get\_picture\_thread()} (background thread)
\item \texttt{\_get\_picture\_thread()} $\rightarrow$ \texttt{RobotController.send\_start()} $\rightarrow$ \texttt{\_send\_command("START\textbackslash n")} or \texttt{START\_CORNER\textbackslash n} based on coordinate system
\item Robot performs positioning and sends "OK"
\item \texttt{RobotController.send\_start()} returns success
\item \texttt{\_get\_picture\_thread()} $\rightarrow$ gets picture from camera \texttt{robot\_ftp\_downloader.py}
\item \texttt{\_load\_robot\_image()} processes downloaded image
\item \texttt{auto\_process\_image()} $\rightarrow$ \texttt{\_start\_auto\_processing()} $\rightarrow$ \texttt{process\_image()}
\end{enumerate}

\textbf{Method B: File Upload (\texttt{simple\_gui.py})}
\begin{enumerate}
\item User clicks file selection $\rightarrow$ \texttt{browse\_image()}
\item \texttt{filedialog.askopenfilename()} opens file picker
\item \texttt{browse\_image()} $\rightarrow$ \texttt{load\_preview\_image()} $\rightarrow$ \texttt{PIL.Image.open()} loads image
\item \texttt{load\_preview\_image()} $\rightarrow$ \texttt{ImageTk.PhotoImage()} creates Tkinter-compatible image
\item \texttt{preview\_label.configure(image=photo\_image)} displays preview
\item \texttt{auto\_process\_image()} $\rightarrow$ \texttt{\_start\_auto\_processing()} $\rightarrow$ \texttt{process\_image()}
\end{enumerate}

\textbf{Method C: Text-to-Image Generation (\texttt{simple\_gui.py})}
\begin{enumerate}
\item User enters text $\rightarrow$ \texttt{quick\_text\_generate()} $\rightarrow$ \texttt{\_text\_generation\_thread()} (background)
\item \texttt{\_text\_generation\_thread()} $\rightarrow$ AI image generation (implementation not shown)
\item Success $\rightarrow$ \texttt{\_text\_generation\_success()} $\rightarrow$ \texttt{\_auto\_process\_generated\_image()}
\end{enumerate}

\textbf{Method D: Canvas Drawing (\texttt{simple\_gui.py})}
\begin{enumerate}
\item User draws on canvas $\rightarrow$ mouse events trigger \texttt{start\_canvas\_drawing()}, \texttt{draw\_on\_canvas()}, \texttt{stop\_canvas\_drawing()}
\item \texttt{save\_drawing()} $\rightarrow$ \texttt{PIL.ImageGrab.grab()} captures canvas
\item \texttt{use\_drawing()} $\rightarrow$ \texttt{load\_preview\_image()} processes captured image
\end{enumerate}

\subsubsection{Phase 3: Image Processing Pipeline}

\paragraph{Main Processing (\texttt{simple\_gui.py} $\rightarrow$ \texttt{robot\_drawer.py} $\rightarrow$ \texttt{image\_processor.py})}
\begin{enumerate}
\item \texttt{process\_image()} $\rightarrow$ \texttt{\_process\_thread()} (background processing)
\item \texttt{\_process\_thread()} $\rightarrow$ \texttt{RobotDrawer.load\_image()} with current settings:
	\begin{itemize}
	\item \texttt{precision}: "high", "medium", "low", etc.
	\item \texttt{enable\_tsp}: Boolean from GUI checkbox
	\item \texttt{detection\_method}: "canny", "threshold", "adaptive"
	\item \texttt{logo\_settings}: Dictionary with enabled/corner/size
	\item \texttt{protect\_logo}: True for logo processing
	\end{itemize}
\end{enumerate}

\paragraph{Image Processing Details (\texttt{image\_processor.py})}
\begin{enumerate}
\item \texttt{ImageProcessor.load\_and\_process\_image()} $\rightarrow$ \texttt{extract\_edge\_following\_path()}
\item \texttt{extract\_edge\_following\_path()}:
	\begin{itemize}
	\item \texttt{cv2.imread()} loads image
	\item \texttt{cv2.rotate(ROTATE\_180)} flips image 180°
	\item \texttt{cv2.mirror} mirrors it horizontally
	\item \textbf{Border Padding}: \texttt{cv2.copyMakeBorder()} adds white padding (unless \texttt{protect\_logo=True})
	\item \texttt{cv2.cvtColor(BGR2GRAY)} converts to grayscale
	\item \texttt{cv2.GaussianBlur()} + \texttt{cv2.medianBlur()} noise reduction
	\end{itemize}

\item \textbf{Edge Detection Methods}:
	\begin{itemize}
	\item \textbf{Canny}: \texttt{cv2.Canny()} $\rightarrow$ \texttt{\_thin\_edges()} morphological thinning $\rightarrow$ \texttt{cv2.morphologyEx(CLOSE)}
	\item \textbf{Threshold}: \texttt{cv2.threshold(THRESH\_BINARY + THRESH\_OTSU)}
	\item \textbf{Adaptive}: \texttt{cv2.adaptiveThreshold(ADAPTIVE\_THRESH\_GAUSSIAN\_C)} with precision-based parameters
	\end{itemize}

\item \textbf{Contour Extraction}:
	\begin{itemize}
	\item \texttt{cv2.findContours(RETR\_LIST, CHAIN\_APPROX\_SIMPLE)} finds contours
	\item \textbf{Filtering}: Remove contours $<$ \texttt{MIN\_CONTOUR\_LENGTH} (10) or $<$ area threshold (adaptive)
	\item \textbf{Border Filtering}: \texttt{\_is\_border\_contour()} removes contours touching image edges (unless \texttt{protect\_logo=True})
	\end{itemize}

\item \textbf{Contour Simplification}:
	\begin{itemize}
	\item \texttt{cv2.approxPolyDP()} with adaptive epsilon based on precision and image properties
	\item Resolution-based factor: 1000000px $\rightarrow$ 3.0, 500000px $\rightarrow$ 2.0, etc.
	\item Scale factor normalization: \texttt{min(2.0, max(0.5, scale * 1000))}
	\item Minimum epsilon: 0.5px, Maximum: perimeter * 0.1
	\end{itemize}

\item \textbf{Path Optimization} (if \texttt{enable\_tsp=True}):
	\begin{itemize}
	\item Contours sorted by length (longest first)
	\item Returns \texttt{\{'contours': simplified\_paths, 'image\_shape': edges.shape, 'simplification\_factor': factor\}}
	\end{itemize}
\end{enumerate}

\paragraph{Coordinate Transformation (\texttt{coordinate\_transformer.py})}
\begin{enumerate}
\item \texttt{CoordinateTransformer.contours\_to\_robot\_coordinates()}:
	\begin{itemize}
	\item Calculates scale: \texttt{min(scale\_x, scale\_y)} where \texttt{scale\_x = effective\_x / width}
	\item \texttt{effective\_x = max\_x - 2*margin\_x}, \texttt{effective\_y = max\_y - 2*margin\_y}
	\item Centers image: \texttt{final\_offset\_x = effective\_offset\_x + margin\_x}
	\item \textbf{Coordinate System Conversion}:
		\begin{itemize}
		\item \textbf{Center Origin}: \texttt{robot\_x = (x * scale) + final\_offset\_x - (max\_x / 2)}
		\item \textbf{Corner Origin}: \texttt{robot\_x = (x * scale) + final\_offset\_x}
		\item Y-axis flip: \texttt{robot\_y = ((height - y) * scale) + final\_offset\_y - (max\_y / 2)}
		\end{itemize}
	\end{itemize}

\item \textbf{Path Smoothing} (if enabled):
	\begin{itemize}
	\item \textbf{Bezier}: \texttt{\_smooth\_path\_bezier()} with quadratic curves
	\item \textbf{Catmull-Rom}: \texttt{\_smooth\_path\_catmull\_rom()} with cubic splines
	\end{itemize}

\item \textbf{Point Filtering}: \texttt{\_filter\_min\_distance()} removes points closer than \texttt{MIN\_DISTANCE\_THRESHOLD} (1.0mm)
\end{enumerate}

\paragraph{Logo Processing (if enabled)}
\begin{enumerate}
\item \texttt{RobotDrawer.generate\_logo\_coordinates()}:
\begin{itemize}
\item Loads \texttt{logo\_short.png}
\item \texttt{ImageProcessor.extract\_edge\_following\_path()} with \texttt{protect\_logo=True}
\item Scales logo to \texttt{size\_mm} while maintaining aspect ratio
\item Positions at top-right corner with 5mm margin
\item \textbf{Logo Flipping}: \texttt{x = logo\_x\_offset + logo\_width\_mm - (px * scale\_factor)} (horizontal mirror)
\item Coordinate system conversion (center/corner origin)
\item Minimum distance filtering
\item Appends logo contours to main drawing points
\end{itemize}
\end{enumerate}

\subsubsection{Phase 5: Robot Connection and Preparation}

\paragraph{Connection Management (\texttt{simple\_gui.py} $\rightarrow$ \texttt{robot\_communication.py})}
\begin{enumerate}
\item User clicks connection toggle $\rightarrow$ \texttt{toggle\_connection()}
\item \texttt{toggle\_connection()} $\rightarrow$ \texttt{\_connect\_thread()} (background)
\item \texttt{\_connect\_thread()} $\rightarrow$ \texttt{RobotController.connect()}
\item \texttt{RobotController.connect()}:
	\begin{itemize}
	\item \texttt{socket.socket(AF\_INET, SOCK\_STREAM)} creates sockets
	\item \texttt{socket.connect((ip, port))} connects to port 1025 (right arm)
	\item \texttt{socket.connect((ip, port\_l))} connects to port 1026 (left arm)
	\item Returns success status
	\end{itemize}

\item \textbf{Robot Initialization}
\item \texttt{RobotController.send\_start()} or \texttt{start\_without\_camera()}:
	\begin{itemize}
	\item Sends "START\textbackslash n" or "START\_CORNER\textbackslash n" based on coordinate system
	\item Robot performs: positioning
	\item Robot responds "OK" after \textasciitilde2 seconds
	\end{itemize}
\end{enumerate}

\subsubsection{Phase 6: Drawing Execution}

\paragraph{Single-Arm Drawing (\texttt{simple\_gui.py} $\rightarrow$ \texttt{robot\_drawer.py} $\rightarrow$ \texttt{robot\_communication.py})}
\begin{enumerate}
\item User clicks "4. START DRAWING" $\rightarrow$ \texttt{start\_drawing()} $\rightarrow$ \texttt{start\_robot\_drawing()}
\item \texttt{start\_robot\_drawing()} $\rightarrow$ \texttt{RobotDrawer.draw()} with progress callback
\item \texttt{RobotDrawer.draw()} $\rightarrow$ \texttt{RobotController.draw\_paths()} with batch mode
\item \texttt{RobotController.draw\_paths()} $\rightarrow$ \texttt{\_draw\_with\_ultra\_fast\_mode()} (if batch enabled)
\end{enumerate}

\paragraph{Batch Drawing (\texttt{robot\_communication.py})}
\begin{enumerate}
\item \texttt{\_draw\_with\_ultra\_fast\_mode()}:
	\begin{itemize}
	\item \textbf{Pen Management}: \texttt{send\_pen\_up()} (already up), \texttt{time.sleep(0.02)}
	\item \textbf{Per Contour Loop}:
		\begin{itemize}
		\item \texttt{should\_stop()} check for emergency stop
		\item \texttt{\_transition\_to\_start()}: Horizontal U-shape movement
			\begin{itemize}
			\item \texttt{send\_between\_command("RETREAT\textbackslash n")} moves back horizontally (±80mm X)
			\item \texttt{send\_move()} to Y-level of next contour start
			\item \texttt{send\_move()} forward to the actual start position
			\end{itemize}
		\item \texttt{send\_pen\_down()}, \texttt{time.sleep(0.02)}
		\item \texttt{send\_move()} to first point with pen down
		\item \textbf{Batch Processing}: \texttt{send\_batch\_moves\_ultra\_fast()} for remaining points
			\begin{itemize}
			\item Groups points into batches (dynamic sizing based on coordinate length)
			\item \texttt{send\_batch\_moves()} $\rightarrow$ \texttt{\_send\_command(f"BATCH,\{coords\}\textbackslash n")}
			\item 80-character command limit handling with batch splitting
			\end{itemize}
		\item \texttt{send\_pen\_up()}, \texttt{send\_between\_command(next\_start)} for retreat
		\end{itemize}
	\item \textbf{Progress Tracking}: Updates via \texttt{progress\_callback(current\_batch, total\_batches, points\_sent, total\_points)}
	\end{itemize}
\end{enumerate}

\paragraph{Dual-Arm Drawing (\texttt{robot\_drawer.py} $\rightarrow$ \texttt{robot\_communication.py})}
\begin{enumerate}
\item \texttt{RobotDrawer.draw\_dual()} (alternative path):
	\begin{itemize}
	\item \texttt{master\_slave\_assign\_contours()} assigns contours to right/left arms
	\item Creates forbidden zones around master contour with circular buffers + tail extension
	\item \texttt{RobotController.draw\_paths\_dual()} with threading
	\item \textbf{Threaded Execution}: \texttt{t\_right} and \texttt{t\_left} threads with \texttt{threading.Barrier(2)} synchronization
	\item \textbf{Per-Step Processing}:
		\begin{itemize}
		\item Collision avoidance: \texttt{\_conflicts\_with\_peer()}, \texttt{\_wait\_for\_peer\_retreat()}
		\item \texttt{\_transition\_to\_start()} with side-specific X offsets
		\item Simultaneous contour drawing with barrier synchronization
		\item WAIT commands for synchronization between arms
		\end{itemize}
	\end{itemize}
\end{enumerate}
